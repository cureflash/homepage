# 朝6時 運用レポート — master instructions

目的: 毎朝6時に、Gmail整理、直近予定、scheduled taskの進捗監視、チャット履歴上の未完了タスク整理を1つの運用レポートとして本人へ返す。

## Gmail

- 接続済み本人Gmailを正規に解決して使用する。アドレスを推測しない。
- 迷惑メール・ゴミ箱は対象外。
- 受信から48時間以上経過した未読メールは、内容を確認したうえで既読化してよい。既読化したものは送信者・件名・要約・理由を報告する。
- 要対応メールにはスターを付け、対応済みメールの不要なスターは解除する。自動で付けたスターは原則1日後に解除対象として見直す。
- GitHub通知メールは受信箱整理のためゴミ箱へ移してよい。ただしCI失敗の事実自体は進捗レポートから消さない。
- 新着・重要・要対応メールは、送信者、件名、要点、必要な対応、期限を報告する。

## Calendar

- Gmail内の確定した面接、試験、勤務、予約、締切などカレンダー登録すべき予定をGoogle Calendarと照合する。
- 既存予定と重複させず、確定情報のみ登録する。
- 変更・キャンセルが確認できた場合は既存イベントを修正または削除する。
- 今日・明日・明後日の予定を日別に報告し、予定なしの日も明記する。

## Scheduled task progress

- 現在のscheduled tasks / automationsを確認し、有効・停止中を区別する。
- 各進行中workerについて、可能な限り対象GitHub repositoryの最新main、MASTER_INSTRUCTIONS、EXECUTION_PLAN、STATUS、HANDOFFを正本として読む。
- 会話中の古い進捗値よりGitHub正本を優先する。
- 各workerについて少なくとも次を報告する: 現在phase/task/checkpoint、完了量、残量、次の具体作業、CI/Actions/blocker、最終実行状況。
- 残量は問題数、PDF数、単元数、checkpoint数、phase/task数など正本で測れる単位を使う。推測しかできない場合は「残量不明」とする。
- 停止中taskは、分かる範囲で「意図的停止」「統合済み/重複」「CI失敗」「ユーザー操作待ち」「完了」「状態不明」に分類する。
- 似たworkerの重複は指摘するが、本人の明示指示なしに有効化・無効化・削除・時間変更をしない。

## Chat history task inventory

- 最近のチャット履歴・personal contextから、scheduled task以外も含めた主要な未完了タスクを抽出する。
- 「進行中」「停止/保留」「ユーザー操作待ち」「完了」に分類する。
- GitHub正本とチャット履歴が食い違う場合はGitHubを優先し、食い違いを報告する。

## Report order

1. 要対応メール
2. 今日・明日・明後日の予定
3. 自動作業サマリー: 現在地点 / 残量 / blocker / 次工程
4. 停止・保留タスク
5. チャット履歴から見つかったその他の進行中タスク
6. 今日本人が判断・操作すべき事項を最大5件、優先順

何もなければ「今日の要判断事項なし」と明記する。
