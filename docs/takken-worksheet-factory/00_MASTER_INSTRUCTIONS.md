# 宅建 Worksheet Factory — MASTER INSTRUCTIONS

このファイルは、宅建教材の自動生成を行うすべてのScheduled Task / agent / runnerが**最初に読む正本手順書**である。

## 1. 目的

`cureflash/homepage` に、2026年度宅地建物取引士資格試験に対応した、無料で利用できる宅建教科書・学習プリント・問題演習の生成基盤を構築する。

最初の主目的は、歴史プリントと同じ思想で、単元ごとの低密度A4教材を大量に生成できる「宅建プリント工場」を作ること。

人手でHTML/PDFを1枚ずつ作らない。**構造化された正本データから、Web教科書・解説プリント・穴埋めプリント・解答・将来の一問一答/四択を派生生成する。**

## 2. 正本パスと移転性

### 実装正本

`qualifications/takken/`

宅建サイト本体、教材データ、生成器、PDF/印刷用表示、公開セレクタはこのディレクトリ配下に自己完結させる。

### 運用正本

`docs/takken-worksheet-factory/`

毎回必ず以下を読む。

1. `00_MASTER_INSTRUCTIONS.md` — 本ファイル。変更不可の基本方針
2. `20_EXECUTION_PLAN.md` — 固定の生成順・Phase・未完了queue
3. `STATUS.json` — 現在地点、batch target、未検証backlog
4. `90_HANDOFF.md` — 直前runの実装内容・検証・注意点

### 移転ルール

将来、別ドメイン、別repo、`/takken/`、`/shikaku/takken/` 等へ移動できるようにする。

- ドメイン名を実装へ直書きしない。
- root absolute path (`/assets/...`) を原則使わない。
- 同一ディレクトリ配下の相対参照または明示的なbase設定を使う。
- 教材データとレンダリングを分離する。
- siteName / qualificationName / basePath 等はconfigに集中させる。
- 宅建固有データを共通UIロジックへ埋め込まない。
- `qualifications/takken/` を丸ごと移せば動かせる構造を維持する。

## 3. 試験年度と法令基準日

現在の製作対象は**2026年度（令和8年度）宅建試験**。

一般財団法人不動産適正取引推進機構（RETIO）の公式試験概要により、宅建試験は50問・四肢択一式で、**出題の根拠となる法令は試験年度の4月1日現在施行されているもの**。2026年度は**2026年4月1日現在施行**の法令を基準とする。

公式参照:
- https://www.retio.or.jp/exam/exam_detail/
- https://moushikomi.retio.or.jp/
- https://www.retio.or.jp/exam/past_ques_ans/other/

教材データには必ず `examYear: 2026` と `lawAsOf: "2026-04-01"` を持たせる。

将来年度を更新するときは、古い教材をそのまま上書きして「最新」としない。法改正差分を確認し、`lawAsOf` を更新したことを明示する。

## 4. 情報源の優先順位

宅建は法令教材であり、曖昧な二次情報から生成してはいけない。

### 最優先（一次・準一次資料）

1. e-Gov法令検索 — 現行法令本文
   - https://elaws.e-gov.go.jp/
2. 国土交通省
   - 宅建業法、都市計画、建築、不動産制度等
3. 一般財団法人 不動産適正取引推進機構（RETIO）
   - 試験概要、公式過去問、正解番号、試験制度
4. 国税庁
   - 国税分野
5. 総務省・地方自治体等の公式資料
   - 地方税、固定資産税等
6. 法務省
   - 民法、不動産登記等に関する公式情報

### 補助資料

- 信頼できる法令解説・公的FAQ
- 判例確認が必要な場合は裁判所等の一次資料

### 禁止

- まとめサイトだけを根拠に確定する。
- 予備校・ブログ・YouTubeの説明を一次根拠としてコピーする。
- 市販テキストの文章・図表・問題文を複製する。
- AIの記憶だけで法令、期限、金額、人数要件、例外を確定する。
- 条文を確認せず「一般にこう」と推測して教材化する。

## 5. 出題範囲の大分類

学習サイト上は、受験者が理解しやすい次の4分野へ整理する。

1. `takken-gyoho` — 宅建業法
2. `rights` — 権利関係
3. `legal-restrictions` — 法令上の制限
4. `tax-other` — 税・その他

公式試験範囲の7項目との対応をメタデータとして保持し、サイト上の4分類だけを公式分類と誤認させない。

## 6. 通常Scheduled Run — GENERATE backlog mode

歴史プリント工場と同じく、通常スケジュール実行は**GENERATE専用**。

1. 最新`main`を取得する。
2. `00_MASTER_INSTRUCTIONS.md`、`20_EXECUTION_PLAN.md`、`STATUS.json`、`90_HANDOFF.md`を読む。
3. `STATUS.json.active_unit` とexecution planの最初の未生成単元を突合する。
4. **1runにつき20単元の新規GENERATEを通常目標**とする。
5. 20単元に達するため章・分野境界を跨いでよい。ただし固定順序は守る。
6. 各単元ごとに一次資料候補を確認する。
7. 事実・ルールを構造化データへ落とす。
8. 学習者向け文章は必ずオリジナルの平易な日本語で書く。
9. 新規教材はすべて `pending_factcheck` とする。
10. `STATUS.json.unverified_backlog` にunit IDを追加する。
11. 未検証教材は公開セレクタ、配布ページ、sitemapへ出さない。
12. run終了時は次の未生成単元へ`active_unit`を進める。
13. 通常runでFACTCHECKへ自動遷移しない。
14. 実装、検証結果、残課題を`90_HANDOFF.md`へ書く。

20単元は通常目標であり、弱い資料で無理に数を埋めるためのノルマではない。一次資料不足、法改正確認不能、実装障害等がある場合は、安全に生成できた最大の連続batchで止め、exact blockerをHANDOFFへ記録する。

## 7. FACTCHECK — 明示指示時のみ

`pending_factcheck` が溜まっているだけではFACTCHECKを開始しない。

ユーザーが明示的にFACTCHECKを指示した場合のみ、独立工程として行う。

FACTCHECKでは生成時の参照を信用せず、各単元を一次資料から再確認する。

最低確認項目:

- 2026-04-01時点の施行法令か
- 主体（誰がする/できる/義務を負う）
- 時期・期限
- 金額・割合・面積・人数・期間
- 原則と例外
- 「できる」「しなければならない」「してはならない」の区別
- 売買/賃貸、宅建業者/一般人、代理/媒介等の適用条件
- 法改正で過去問の正答が変化していないか
- 出典URLが実際に該当claimを支えるか
- 問題と解答に一意性があるか

通過した単元だけ `verified` に変更し、公開可能とする。


## 9. 穴埋め対象のルール

機械的に名詞を空欄化しない。

穴埋め候補は、試験上覚える価値が高いものだけを明示する。

優先対象:

- 法律名・制度名
- 条文番号（学習価値がある場合）
- 主体
- 期間・期限
- 数字・割合・金額
- 書面名
- 許可/届出/免許等
- 原則と例外を分けるキーワード

避ける対象:

- 文脈からどうとでも答えられる一般名詞
- 長すぎる文章
- 単独では意味がない助詞・修飾語
- 試験上の重要性が低い数字

seedによる穴埋め選択は決定論的にし、同じseedなら同じ問題が出ること。

## 10. プリント形式

歴史プリントと同系統のUI/印刷思想を使う。

1単元から最低3モードを生成可能にする。

1. `study` — 解説。重要語を強調
2. `worksheet` — 穴埋め
3. `answer` — worksheetと同一配置で解答表示

A4印刷を前提とし、1単元に情報を詰め込みすぎない。

宅建では写真を無理に使わず、必要に応じて以下を優先する。

- 比較表
- フロー図
- 原則/例外ボックス
- 時系列
- 主体関係図
- 数字・期限まとめ

生成AIによる装飾画像は原則不要。学習効果のない画像で紙面を埋めない。

## 11. 問題生成ルール

教科書データを正本にし、将来そこから以下を派生できるようにする。

- 一問一答
- ○×
- 四肢択一
- 分野別確認テスト
- 50問模試

### 四肢択一

宅建本試験と同様に「正解が一つ」にできる問題を原則とする。

誤答肢はランダムな嘘ではなく、次のような典型的混同から作る。

- 主体の入替え
- 契約前/契約後の入替え
- 数字・期間の入替え
- 原則/例外の入替え
- 必要/不要の入替え
- 売買/賃貸の適用範囲混同
- 知事/国土交通大臣等の権限混同

ただし、未検証の自動生成問題は公開しない。

## 12. 過去問ルール

RETIOが公開する公式過去問を参照してよいが、次を守る。

- 公式公開ページの利用条件を都度確認する。
- 過去問本文を大量転載する前に権利・利用条件を確認する。
- 法改正により現在法と一致しない問題があることを前提にする。RETIO自身も過去問ページで注意喚起している。
- 古い正解を現在法の解説として流用しない。

初期Phaseでは過去問転載より、**現行法に基づくオリジナル類題**を優先する。

## 13. 公開条件

公開できるのは次を全て満たす単元だけ。

- `factcheckStatus === "verified"`
- 2026-04-01基準法令を独立確認済み
- 各claimに根拠がある
- 穴埋めと解答が一致
- seed再現性あり
- 印刷崩れなし
- 誤解を招く省略がない
- 公開用selector/catalogへ登録済み

`pending_factcheck` はrepo内に保持してよいが、ユーザー向けページには出さない。

## 14. Git運用

- 作業開始時に最新`main`を確認する。
- 他workerの変更を巻き戻さない。
- 既存変更がある場合はreconcileしてから作業する。
- 一つのrunで変更した内容は、可能な範囲で論理的なcheckpointにまとめる。
- テスト/構文検証を実行してからcommit/PR/mergeする。
- push競合があればforce pushしない。最新mainとreconcileする。
- `STATUS.json` と `90_HANDOFF.md` は実装状態と必ず一致させる。

## 15. 完了の定義

このfactoryの初期完成は、次を満たした状態。

- 4分野の固定queueを一巡
- 全単元の構造化教科書データが存在
- 解説/穴埋め/解答が同じデータから生成可能
- FACTCHECK済み単元だけ公開できる
- PDF/印刷導線が機能
- 将来、一問一答・四択・模試へ同じ正本データを再利用可能
- `qualifications/takken/` を別場所へ移しても大幅修正不要

## 16. 最優先原則

**速度より、法令の正確性と更新可能性を優先する。**

ただし、正確性確保を理由に生成工程と独立FACTCHECK工程を混ぜない。通常Scheduled Runは20単元GENERATEしてbacklogへ積み、独立FACTCHECKはユーザーから指示されたときにまとめて行う。
