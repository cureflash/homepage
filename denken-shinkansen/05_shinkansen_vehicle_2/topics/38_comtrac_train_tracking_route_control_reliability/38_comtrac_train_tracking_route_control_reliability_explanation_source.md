## 2. 状態データとイベント処理

制御・運行管理システムでは、対象の現在状態を表すデータと、状態を変えるイベントを分けて考えると整理しやすい。

例として教材用の抽象状態を

- `WAIT`: 待機
- `READY`: 実行可能
- `RUN`: 実行中
- `BLOCKED`: 条件待ち

と置く。イベント `E` により

`state_next = f(state_current, E)`

と状態が変わる。この式は一般的な有限状態機械の表現であり、COMTRACの内部状態定義ではない。

### 割込み

CPUが通常処理中でも、外部・内部イベントに応じて所定の処理へ制御を移す仕組みが割込みである。時刻到来、入出力完了、異常通知などのイベント駆動処理に使われる。

試験では「一定時間ごとに必ず順番に調べる処理」と「イベント発生時に処理を起動する割込み」を区別する。

### FIFOと優先度

FIFOは First In First Out、先に入ったものを先に取り出す方式である。待ち行列の基本であり、同一優先度の要求を到着順に扱う場合に使える。

優先度制御では、高優先度の処理が継続的に到着すると低優先度処理が長時間実行されないことがある。これを starvation（飢餓）という。

### スループット

単位時間当たりに処理できる仕事量をスループットという。応答時間と同じ概念ではない。応答時間は1要求の完了までの時間、スループットは時間当たりの処理量である。

## 3. ブール代数

論理変数を `0` と `1` で表す。

- AND: `A・B`
- OR: `A+B`
- NOT: `Ā`

基本則:

- `A・0=0`
- `A・1=A`
- `A+0=A`
- `A+1=1`
- `A・A=A`
- `A+A=A`
- `A・Ā=0`
- `A+Ā=1`

ド・モルガン則:

`overline(A・B) = Ā + B̄`

`overline(A+B) = Ā・B̄`

試験では真理値表、論理式、ゲート回路を相互変換できることが重要である。

## 4. 組合せ回路と順序回路

### 組合せ回路

現在の入力だけで出力が決まる。

`Y(t)=f[X(t)]`

加算器、デコーダ、論理判定回路等が典型である。

### 順序回路

現在入力だけでなく過去の状態にも依存する。

`S(t+1)=f[S(t), X(t)]`

`Y(t)=g[S(t), X(t)]`

この「状態を保持する」ためにフリップフロップ等を使う。

### フリップフロップ

フリップフロップは二つの安定状態を持ち、1 bitの状態を保持できる。順序回路では複数のフリップフロップを組み合わせて状態を表す。

状態遷移表・状態遷移図から次状態論理を作り、必要なら論理式を簡単化する。

## 5. 論理最小化

同じ真理値表でも論理式の書き方は複数ある。ゲート数や論理項を減らすため論理最小化を行う。

Quine–McCluskey法は、mintermを体系的にまとめて主 implicant を求める方法である。変数が少ない場合はカルノー図、機械的・体系的に処理したい場合はQuine–McCluskey法という位置付けで理解する。

ここで扱う論理最小化は電験の一般論理回路であり、実際の鉄道安全論理を最小化する設計手順を示すものではない。安全系では機能安全、フェイルセーフ、検証可能性等を含む別の設計要件が必要である。

## 6. シーケンス制御とフィードバック制御

### シーケンス制御

あらかじめ定めた順序・条件に従って動作を進める制御である。

例:

`条件A成立 -> 動作1 -> 条件B確認 -> 動作2`

条件判定、自己保持、インターロック等が代表要素になる。

### フィードバック制御

出力を検出して目標値との差を求め、その偏差に応じて操作量を調整する。

`目標値 -> 比較 -> 制御器 -> 制御対象 -> 出力 -> 検出 -> 比較へ戻る`

順序や条件分岐が主ならシーケンス制御、連続量の偏差を戻して調整するならフィードバック制御、という違いをまず押さえる。

R8一次問8では、マイクロコンピュータ、シーケンス制御、フィードバック制御、角位置センサ、ステッピングモータを関係付けて識別することが求められる。

## 7. 列車追跡と時刻情報を一般情報処理として捉える

JR東海一次資料では、COMTRACが列車運行状況・設備状態を把握し、列車運行管理や進路制御を支援すること、運行条件として到着時刻・発車時刻、番線、列車順序等を扱うことが確認できる。

情報処理として抽象化すると、

1. 列車位置・運行条件等の状態データを受け取る。
2. 現在状態と時刻条件を整理する。
3. 許容される進路・処理を論理判断する。
4. 状態更新後の結果を監視する。

という流れで説明できる。

ただし、実際にCOMTRAC内部でどの順番・周期・データ構造・アルゴリズムを使うかは公開一次資料で確認できていないため断定しない。

## 8. 列車位置検知とインターロック

JRTT一次資料では、軌道回路が列車位置を検知する設備として説明され、連動装置は転てつ器と信号機等を互いに関連付け、衝突や誤進入を防ぐ役割を持つ。

一般化すると、進路を許可するためには複数条件が同時に成立する必要がある。

教材用の単純モデルとして、

`Route_OK = Request ・ Track_Clear ・ Point_Locked ・ Conflict̄`

と置ける。

ここで

- `Request`: 進路要求
- `Track_Clear`: 対象区間に列車がいない
- `Point_Locked`: 転てつ器が所定位置で鎖錠済み
- `Conflict`: 競合進路成立中

とする。

これはブール代数・インターロック概念を学ぶための仮定式であり、実際のCOMTRACや電子連動装置の論理式ではない。

### 教材用状態遷移

進路状態を

`IDLE -> REQUESTED -> LOCKED -> CLEARED -> OCCUPIED -> RELEASED -> IDLE`

と置けば、状態遷移の考え方を説明できる。これも教材用モデルであり、実設備状態名・遷移順を表していない。

## 9. ソフトウェア試験と高信頼化

高信頼システムでは、論理が正しいだけでなく、実装されたソフトウェアが仕様どおり動くか段階的に確認する必要がある。

### 単体試験

モジュール単位で機能を確認する。

### 結合試験

複数モジュールを組み合わせ、インタフェースやデータ受け渡しを確認する。

### ボトムアップ試験

下位モジュールから順に結合する。上位モジュールの代わりにテスト用ドライバを用意する場合がある。

### トップダウン試験

上位モジュールから下位へ結合する。未完成の下位モジュールの代わりにスタブを使う場合がある。

### ブラックボックス試験

内部構造ではなく、仕様に基づいて入力と出力の関係を確認する。

R29一次問8の固定答案要素は、ウォーターフォール型の工程、ボトムアップ、結合試験、ドライバ・スタブ、ブラックボックス試験の区別に接続する。

## 10. 冗長化

単一故障で全機能を失わないよう、設備や経路を複数用意する考え方が冗長化である。

### n+1

必要容量を `n` 台で満たし、さらに1台分の予備を持つ構成を `n+1` と呼ぶ。1台故障しても必要容量を維持できることを狙う。

ただし、故障モード、共通原因故障、保守状態、切替方式等によって実際の信頼度は変わる。「n+1だから必ず無停止」とは言えない。

### バイパス

主系統が故障・保守状態でも別経路で負荷へ供給する経路をバイパスという。UPSでは商用系統との同期、切替条件、容量等が重要になる。

### 並列冗長

複数装置を並列に動作させ、1系故障時にも残りで機能を継続させる方式がある。独立故障を仮定できるか、共通部分に単一点故障がないかを確認する必要がある。

H26一次問3はUPSを題材として直流スイッチ、バイパス、並列冗長、同期、n+1容量を問う。これらを一般信頼性設計として学ぶ。

## 11. 信頼性と可用性

### 信頼性

所定条件・所定時間で機能を維持する性質である。修理可能系ではMTBFを指標として使う場合がある。

### 保全性

故障後に機能を復旧しやすい性質で、平均修復時間MTTR等を使う。

### 可用性

必要な時に機能を利用できる割合を表す。単純な二状態・修理可能系の教材モデルでは、定常可用性を

`A = MTBF / (MTBF + MTTR)`

と表せる。

不稼働率は

`U = 1 - A = MTTR / (MTBF + MTTR)`

である。

この式をCOMTRAC実値へ代入しない。故障率分布、保守遅延、共通原因、計画停止等を無視した単純モデルであることを明示する。

### 並列系の教材モデル

独立した二系統の各可用性が `a` で、どちらか一方が利用可能ならシステムが利用可能という仮定では

`A_parallel = 1 - (1-a)^2`

となる。

これは独立故障・完全切替等を仮定した教材計算であり、JR東海第二総合指令所の実構成やCOMTRAC装置構成を表すものではない。

## 13. 例題1 — 基礎: ブール論理

教材用進路条件を

`R = A・B・C̄`

とする。

`A=1`, `B=1`, `C=0` のとき、

`R = 1・1・1 = 1`

で進路許可条件が成立する。

`C=1` なら

`C̄=0`

なので

`R=0`

となる。

狙いはANDとNOTの同時使用を確認することであり、実設備論理を再現することではない。

## 14. 例題2 — 本試験標準: 状態・FIFO・割込み

三つの処理要求 `P1`, `P2`, `P3` が同一優先度で時刻順に到着し、待ち行列がFIFOだとする。

到着順が

`P1 -> P2 -> P3`

なら取り出し順も

`P1 -> P2 -> P3`

である。

一方、処理中に高優先度割込み `I` が発生し、割込み受理条件を満たす場合は、通常処理を一時中断して割込み処理へ制御を移す。

試験ではFIFOを「優先度順」と誤認しない。また、割込みを単なる一定周期ポーリングと混同しない。

## 15. 例題3 — 複合: 可用性と冗長化

単純二状態の修理可能装置を仮定し、

`MTBF = 1000 h`

`MTTR = 2 h`

とする。

可用性は

`A = 1000/(1000+2)`

`= 0.998004...`

したがって約 `99.8004 %` である。

さらに、独立・完全切替を仮定して同じ可用性の二系統を並列化すると、教材モデル上は

`A_parallel = 1 - (1-0.998004)^2`

`≈ 0.999996`

となる。

ただし実システムでは共通原因故障、切替失敗、保守待ち、共通電源・通信経路等があるため、この値をそのまま実設備可用性とみなしてはいけない。

## 21. 頻出ミス

1. 組合せ回路と順序回路を逆にする。
2. フリップフロップを「入力だけで出力が決まる素子」と誤認する。
3. FIFOを優先度順と誤認する。
4. 割込みとポーリングを同じものとする。
5. スループットと応答時間を混同する。
6. シーケンス制御とフィードバック制御を混同する。
7. n+1を「n台全部が予備」と誤認する。
8. 可用性を信頼性と同義とする。
9. 並列冗長化だけで共通原因故障が消えると考える。
10. 教材用の論理式・状態遷移を実際のCOMTRAC実装と誤認する。

## 23. 公式・解法まとめ

- 状態遷移: `S_next=f(S_current, X)`
- 組合せ回路: `Y=f(X)`
- 順序回路: `S_next=f(S,X)`, `Y=g(S,X)`
- ド・モルガン: `overline(A・B)=Ā+B̄`, `overline(A+B)=Ā・B̄`
- 単純二状態修理系の可用性: `A=MTBF/(MTBF+MTTR)`
- 独立二並列の教材モデル: `A_parallel=1-(1-a)^2`
- FIFO: 先入れ先出し
- starvation: 低優先度処理が実行機会を失う状態
- n+1: 必要台数nに予備1台を加える考え方

解法手順:

1. 問題が論理、状態、OS、試験、信頼性のどの分野か判定する。
2. 用語を機能で区別する。
3. 状態問題は現在状態・イベント・次状態を分ける。
4. 論理問題は真理値表またはBoolean式へ落とす。
5. 冗長化問題は必要容量、予備、バイパス、同期条件を確認する。
6. 可用性計算ではMTBFとMTTRの単位をそろえ、成立仮定を確認する。
7. 鉄道へ接続する場合、一般モデルと実設備一次資料の事実を明確に分離する。
